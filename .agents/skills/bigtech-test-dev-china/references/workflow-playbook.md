# 工作流手册

> 用于测试方案、回归策略、压测与故障排查。

## 1. 需求评审最少检查集

- 用户价值：这次改动到底影响哪条核心链路
- 入口与出口：从哪里进，成功/失败分别落到哪里
- 状态流转：哪些状态会变，谁驱动，是否可逆
- 兼容性：老版本、旧数据、灰度期间是否兼容
- 异常路径：超时、重复提交、回调丢失、依赖失败怎么办
- 观测性：日志、埋点、指标、trace 是否提前补齐
- 发布策略：灰度、开关、回滚、数据补偿是否明确

## 2. 测试方案模板

### 风险清单

| 维度 | 典型风险 |
|------|----------|
| 功能正确性 | 状态流转错误、边界未校验、默认值错误 |
| 数据正确性 | 重复写入、脏数据、缓存不一致、异步丢数 |
| 兼容性 | 老接口、老客户端、灰度混部、字段新增删减 |
| 稳定性 | 超时、雪崩、慢 SQL、线程池打满、连接池耗尽 |
| 安全性 | 越权、重放、伪造请求、参数注入 |
| 运维性 | 缺日志、缺开关、无熔断、无法回滚 |

### 用例设计顺序

1. 主成功链路
2. 高概率失败链路
3. 资损/投诉/线上事故风险链路
4. 边界条件
5. 并发、重试、幂等
6. 灰度与回滚

## 3. 回归策略

### 按发布节奏分层

- 提交前：lint、单测、静态检查、契约校验
- CI 冒烟：10 分钟内，拦主链路
- 每日回归：接口为主，覆盖高频业务路径
- 发布前回归：本次变更相关 + 关联高风险模块
- 发布后巡检：线上指标、告警、核心业务探针

### 回归包裁剪原则

- 近期改动路径优先
- 历史高缺陷模块优先
- 核心收入/转化/内容分发链路优先
- 低收益、低稳定性的 UI 自动化用例定期清理

## 4. 压测方案骨架

### 必答问题

- 压什么：接口、链路、任务、消息堆积还是数据库
- 模型是什么：匀速、突刺、波峰波谷、节日洪峰
- 看什么：吞吐、RT、错误率、资源利用率、队列积压
- 降级点在哪：熔断、限流、缓存、降配、异步化
- 停止条件：错误率阈值、关键指标失真、下游保护触发

### 压测结论至少包含

- 单机能力
- 集群能力
- 瓶颈位置
- 安全水位
- 扩容建议
- 风险兜底

## 5. 线上故障排查顺序

1. 先确认影响面：哪些用户、哪些区域、哪些版本
2. 看时间点：是否与发布、配置、依赖抖动对齐
3. 先查变更：代码、配置、数据、流量入口、开关
4. 看四类信号：错误日志、延迟、资源、下游返回
5. 先止血：回滚、限流、降级、熔断、开关关闭
6. 再收敛根因，不在事故进行中追求完美解释

## 6. 复盘模板

### 五段式

1. 事故摘要：一句话说明发生了什么
2. 事件时间线：发现、升级、止血、恢复、复盘
3. 根因链路：不是单点原因，要写出为什么会逃逸
4. 损失评估：业务、用户、工程成本
5. 改进项：按“防再发、早发现、快止血”拆分

### 改进项分类

- 防再发：补校验、补契约、补测试、补门禁
- 早发现：补埋点、补日志、补告警、补巡检
- 快止血：补开关、补降级、补回滚脚本、补演练
