# 面试与晋升

> 用于大厂测试开发面试准备、模拟回答、项目表达和晋升答辩。

## 1. 大厂测开常问能力面

- 你做过最复杂的测试项目是什么
- 一个线上事故你是怎么定位和复盘的
- 自动化框架你怎么设计，为什么这么分层
- 如何平衡质量、效率和发布速度
- 你如何推动开发接受质量门禁
- 你做过哪些平台化/效能提升项目
- 如何衡量测试工作的价值

## 2. 回答结构

### 项目题

1. 背景：业务规模、风险、约束
2. 问题：原来为什么不行
3. 方案：技术设计、分层策略、权衡
4. 落地：推动、协作、阻力
5. 结果：数据变化
6. 反思：哪里做得不够，如何升级

### 故障题

1. 现象
2. 影响
3. 排查路径
4. 止血动作
5. 根因
6. 防再发

## 3. 项目包装禁区

- 只讲执行，不讲设计权衡
- 只讲“我写了很多用例”，不讲解决了什么问题
- 只讲工具名，不讲为什么适合当前场景
- 结果没有数据
- 不承认失败与反思

## 4. 晋升答辩看什么

- 是否从“做测试”升级到“设计质量机制”
- 是否能影响跨团队协作方式
- 是否沉淀平台、标准、模板、门禁
- 是否对效率和事故指标有持续改善
- 是否能培养他人，而不是自己单点扛活

## 5. 可直接套用的表达骨架

### 自动化项目

“当时的问题不是没有自动化，而是自动化太慢、太脆、拦不住主风险。我的设计重点不是补更多脚本，而是重构分层，把接口自动化作为主回归层，UI 只保留核心链路，再把失败诊断信息打透到流水线。最终我们把冒烟反馈从 X 降到 Y，假失败率从 A 降到 B。” 

### 质量治理项目

“这个项目的关键不在于发现更多 bug，而在于把 bug 出现的位置往前推。我们把需求评审、契约校验、发布清单和发布后巡检串起来后，线上事故不只是少了，而且定位成本也明显下降。”

## 6. 模拟面试规则

如果用户要求模拟面试：

- 先确认目标级别：校招 / 社招中级 / 高级 / 专家
- 每轮只问 1 题，追问 1 到 2 次
- 先指出最大问题，再给优化回答
- 默认重点看：结构化、技术深度、量化结果、反思质量
