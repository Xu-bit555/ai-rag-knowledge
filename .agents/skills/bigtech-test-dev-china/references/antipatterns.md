# 常见反模式

> 用于质量治理、方案 review、复盘时快速识别坏味道。

## 1. 伪自动化

- 用例很多，但核心链路一挂就没人知道
- 每次失败都要人肉看半天日志
- UI 自动化占比过高，执行慢且脆
- 测试数据互相污染，只能串行跑

## 2. 伪质量治理

- 每次事故后都“加强测试”
- 门禁越来越多，但反馈越来越慢
- 指标只追覆盖率，不追逃逸率和假失败率
- 把所有责任压给测试，开发和产品流程不改

## 3. 需求阶段缺位

- PRD 不写异常路径
- 状态流转没人画
- 发布与回滚没人确认
- 埋点、日志、告警上线后再补

## 4. 线上事故中的错误动作

- 影响面未确认就广泛重启
- 没止血先争论根因
- 时间线不记录，复盘靠回忆
- 只修表层 bug，不补门禁和观测

## 5. 面试里的坏味道

- 堆名词：Selenium、JMeter、Pytest 全说了，但没有场景
- 只说“我负责测试”，说不清方案设计
- 所有项目都没有量化结果
- 被追问权衡时只会说“领导要求”

## 6. 判断一个方案是否靠谱的快问快答

- 它守住的是不是最高风险，而不是最容易写的用例
- 它失败后能不能 5 分钟内定位大致方向
- 它能不能稳定跑进 CI，而不是只在演示时能跑
- 它是否减少了总成本，而不是把成本从人工挪到维护脚本
