# 自动化与质量门禁

> 用于框架设计、自动化分层、CI/CD 门禁与质量指标。

## 1. 自动化分层原则

- 单测守纯逻辑和边界
- 契约/接口测试守服务交互和状态流转
- UI 自动化只守少量关键主链路
- 线上探针守发布后健康度

不要把“验证成本最低的一层没做好”的问题，推到最慢最脆的 UI 层。

## 2. 好的自动化框架应具备

- 用例分层清晰：冒烟、核心回归、扩展回归
- 数据隔离：账号、环境、租户、幂等 key 可复用
- 失败可定位：日志、请求响应、截图、trace id、重试记录
- 可并发执行：不互相污染，不依赖执行顺序
- 接入流水线简单：本地、CI、预发一致

## 3. 门禁设计

### 推荐四层门禁

| 层级 | 目标 | 典型规则 |
|------|------|----------|
| 开发本地 | 早反馈 | lint、单测、契约检查 |
| CI 冒烟 | 拦显性风险 | 核心接口、构建、依赖连通性 |
| 预发验证 | 拦集成风险 | 主链路回归、灰度验证、配置检查 |
| 发布后巡检 | 快发现 | 业务探针、错误率、核心指标对比 |

### 门禁指标示例

- 构建成功率
- 冒烟通过率
- 核心链路成功率
- 用例平均执行时长
- 假失败率
- 发布后 30 分钟告警数

## 4. 质量指标怎么选

优先能驱动正确行为的指标：

- 缺陷逃逸率
- 需求测试前移率
- 冒烟反馈时长
- 自动化稳定性
- 线上事故由测试缺口导致的比例

谨慎使用容易被刷的指标：

- 用例总数
- 覆盖率单一数字
- 人工执行条数
- 缺陷数绝对值

## 5. 测试左移抓手

- PRD 评审模板
- 接口契约评审
- 静态检查与 schema 校验
- Mock/Stub 提前联调
- 风险需求清单
- 发布清单标准化

## 6. Review 输出模板

### 测试方案 review

- 最高风险点是什么
- 当前方案漏了什么
- 哪些应该前移到开发或契约层
- 哪些不该进入 UI 自动化
- 发布阶段最值得加哪一道门禁

### 自动化方案 review

- 失败是否可定位
- 数据是否隔离
- 执行是否足够快
- 用例是否真的守住了关键风险
- 是否存在大量脆弱选择器、硬编码等待、串行依赖
